## 架构与决策

- `taskfleet/models.py`、`instances.py`、`paths.py`：状态/配置、严格验证与生成、确定性BFS。`engine.py`：状态转移、不变量、事件与快照。
- `allocation.py`、`cnp.py`：关于独立观测的决策；`metrics.py`、`benchmark.py`：M5阶段的共同评估；`__main__.py`：CLI。`scripts/benchmark_extended.py`复用这些模块。
- `api/main.py`直接适配引擎；验证与生成共享Python解析器。`frontend/src/App.vue`负责回放、检查与对比；包含SVG组件、编辑器和日志模块。

FIFO使用`(arrival_tick, ID)`，然后按机器人ID进行处理。CP-SAT最大化基数，随后最小化BFS路径上的距离加两轮搬运，不考虑截止时间或队列。其状态和预算按阶段明确呈现：仅当前分配的最优解，`FEASIBLE`无证明，第二阶段无解但保持可行分配。CNP使用本地报价、承诺与重新报价；发起方选择接收到的报价，无需私有重新计算。无分布式网络。[科学细节](benchmark.zh-CN.md#problème-et-stratégies)。

Vue模块在启动时计算一条轨迹，之后在导航中无需调用API。忽略过时响应，清理计时器；在tick/策略间对比保留，编辑、导入/生成成功或预算变更后无效。蓝色路径来自`robot.path`；紫色连接表示收集与交付，逻辑合理。选择与过滤跟随快照，重叠机器人仍保留在其格子中；CNP的广播仍保留在机器人过滤器中。

<a id="fonctionnement"></a>
## 运行机制

- 网格`[x, y]`，四个邻接格子，每tick一个格子。BFS采用右-下-左-上的分路策略；路径不包含起点，但包含终点。每个机器人与任务的分配唯一，负载兼容。
- 在两端均执行正向搬运，即使两端重合。搬运期间预留站点，机器人数量与负载容量相互独立。截止时间仅作为信息提示。
- 顺序：当前tick进行分配；增量更新；到达与可用性更新；按字典序逐个机器人执行操作；释放；快照。一个tick的分配在下一个tick生效；一个释放的格子可在下一个tick重新使用。
- `[start_tick, end_tick)` 样式的标识符是不可变占位符：必须精确保留每一个实例，不得更改、合并或发明标识符。必须保持 Markdown 强调标记和链接括号的结构有效性。
保留每一个否定、条件、计划状态、限制、反例以及验证、实验性、提议、人工辅助和自主结果之间的区别。绝不将被排除的功能转化为支持的功能。
保留所有软件和项目名称、标识符和值。精确翻译技术术语。Windows 是一个操作系统，而不是一个窗口。软件分支是分支，而不是餐叉。训练是模型训练，而不是人类课程。游戏时钟是模拟步骤，而不是股票市场价格变动。一个保留集是预留的评估集。规划是行动规划，调度是时间调度。来源依据核验是将声明与源证据进行比对。输出仅 JSON。
- `run(until)` 使用绝对时钟；不传参时，持续运行至终点。`finished` 指定该终点，`all_tasks_completed` 表示完成。不包含任何虚构交付。
- `trace()` 包含初始配置、事件、快照和当前状态，这些均被分离。初始快照在分配前；后续快照在时钟步进后。视图在最后一个时钟步进时使用 `current`。自动轨迹与相同实例、策略和预算的轨迹重复；实时数据被排除。

JSON 描述初始配置：需要 `width`、`height`、`robots`、`tasks`；障碍、资源、终点、种子和不可用性为可选。机器人：ID、位置、容量；任务：ID、采集、目的地、载荷/搬运、截止时间与到达时间；不可用性：机器人与时间区间。整数严格类型，ID 在类型内唯一，每个格子对应一个资源；布尔值/浮点数，未知字段和重复的 JSON 键被拒绝。`from_dict`、`loads_instance`、`load_instance` 和 `Instance.to_dict()` 共享相同格式。[示例](../examples/simple.json) 和解析器提供了完整的字段/默认值。

验证确保容量/可达性，不提前完成至终点。生成使用本地种子，保留网格/障碍/资源/终点，替换机器人/任务并移除旧日历。引擎不使用任何随机性。CP-SAT：一个工作进程，种子为 0；在已验证的版本/平台中可重现选择。不支持对模型的直接变异。

<a id="limites-connues"></a>
## 已知限制

不支持物理碰撞、电池、抢占、搬运或队列预测。暂停可能独占一个站点；顺序为字典序，但无公平性保障。五种合成种子，makespan 依赖于任务完成，时间变量：不存在普遍优势或全局动态最优解。

V1 版本为同步路线；V2 版本为异步且有界，完整内存中轨迹，无服务器持久化；仅适用于小规模实例。CORS 仅限前端本地访问 5173 端口。内部错误被记录并隐藏于客户端；非 JSON 错误保留 HTTP 状态码。已弃用 Starlette/HTTPX 在 TestClient 中。已移除 Streamlit；Matplotlib 为可选用于图表，pandas 作为 OR-Tools 的中间件。

<a id="fonctionnement-1"></a>
### 运行状态

**M7。** `plan_schedule`要求在有限的绝对时间范围内完成所有观察到的任务，包括到达时间、优先级、BFS路径、容量、搬运和站点。所有活跃承诺被冻结。站点保留优先级ID、在下一个时钟周期释放，并在暂停期间保留预留。目标为先最小化总延迟，再最小化makespan；第二次求解需基于第一次求解的最优解。每阶段使用确定性CP-SAT时间预算，一个工作进程和种子0；这并非全局截止时间。若第二阶段无解，仍可保留第一阶段的可行计划。

`solve_schedule` 是一个离线预言机，知晓所有任务/到达事件和提供的日历；基准测试名义上排除故障。`execute_schedule` 在 V1 中重放分配日期，然后检查拒绝和收货/交付偏差；它不会强制移动。`run_rolling` 仅观察已揭示的任务和当前状态，不包含未来日历。在 `min(horizon, tick + window)` 之前，进行周期性或任务/可用性变更时的重新规划，假设未来可用性为乐观情况。若无可行解，则采用 FIFO 策略，不丢失待处理任务列表或承诺。

`optimize_priority` 列出每个机器人固定的分配和订单，直到 `max_policies`。每个声明日历中均重放相同的策略；仅能将已揭示的队首任务分配给可用机器人。所有场景必须结束。最小最大值策略最小化最坏延迟，然后是最坏的周期时间。`OPTIMAL` 要求完整枚举该类情况；截断搜索将得到 `FEASIBLE` 或 `UNKNOWN`。

**M8.** 每个 `LocalAgent` 接收其独立的机器人、网格以及已到达的公开任务 `PENDING`，不包含其他机器人的状态/成本或未来事件。领域：等待 `None` 与兼容任务；自身成本 = 两次 BFS 距离 + 两次搬运，不预估队列。等待和冲突惩罚被校准，优先避免冲突，然后是任务数量和成本。领域在传播时不计成本；当两个代理共享一个任务时，它们成为邻居。

初始阶段独立初始化至最低 `(coût, ID tâche)`，然后交换选定值。在每次 DSA-B 同步轮次中，以概率 `p` 应用严格改进；相等则保持原选择。振荡持续不断被计数。确认阶段交换 `claim` 然后 `confirmed`：最小 ID 保留争议任务，失败者等待而不重新分配。中央引擎或修复器的拒绝均不用于解决冲突。预算计入所有传输，包括领域发现，且为确认预留；逻辑消息单独计数。

LLM 经验复用领域、消息和确认，但直接应用返回的合法动作，不经过 DSA 优化过滤或概率抽样。`UNCHANGED_LLM` 仅表示动作不变。求解器仍为固定分配：`--execute` 在 V1 中重放该分配，不将 DSA/LLM 转化为引擎的连续策略。

**M9.** 一个计划包含在第 0 个时间步的出发，随后是正交移动或等待；禁止顶点冲突和边的同步交换。一旦首次访问，目标即成为吸收性目标；其占用状态持续至时间边界。成本：首次到达时间步的总和，包括到达前的等待时间。

优先规划保留了`(position, tick)`顶点、带时间戳的边和持续目标；A*同时验证剩余视界中目标的可达性。CBS在首次冲突处创建两个分支；每个分支仅约束并重新规划受影响的单个代理；其队列最小化各成本之和。`validate_plan`在任何指标发布前独立控制单元、移动、目标、视界和碰撞。`SOLVED`验证一个有效计划；`optimal`仅涉及该模型中的CBS/预言机。`NO_SOLUTION_WITHIN_HORIZON`证明在视界内无解；`PRIORITY_FAILED`未证明任何不可行性，而`BUDGET_EXHAUSTED`仍为未知结果。

**M10.** 局部观察：网格、干净机器人、公开任务`PENDING`、自有成本与合法掩码，无其他机器人、未来任务、资源或未来日程。动作：任务ID或`None`；遗漏的机器人等待。各提案在状态转移前使用相同观察；竞争性声明通过机器人ID进行区分。超出掩码的动作被拒绝，冲突被单独计数。在接受分配后，`step`精确推进一个V1时钟步，不规避碰撞。

状态转移后的共同奖励：是未完成任务数量的相反数，包括正在进行的任务；不包含任何直接的延迟、距离或冲突项。`terminated`要求所有已完成任务，即使为未来任务；`truncated`在未完成的情况下标记视界达到。更新Q不将值延长至超过终止或截断点。

表格使用精确观察，不包含绝对时钟步或机器人ID，包含任务年龄与剩余期限；网格和任务ID保留在键中。独立Q学习，`alpha=0.2`，`gamma=1`，均匀探索与合法最大值的随机拆分。记录的经验训练了四实例中每粒种子0/1/2的60个回合，ε值从0.30降至0.05。每十个回合保存一次检查点；在两个验证实例中，平均回报最佳，平局时排名第一。表格以JSON格式保存、重新加载并冻结，用于前三次测试实例和两个分布外实例。评估不创建任何状态，也不执行任何更新。

**Ollama.** 客户端调用`/api/chat`，传入一个限制`action`的JSON模式，仅允许合法值；随后精确验证该键及其所属域。M8传输本地观察和邻近消息；M10传输其本地观察。若出现错误、无效响应或预算耗尽，客户端选择等待`None`，该等待被计数并记录为备用，绝不会作为成功生成。调用、令牌、延迟、服务器时长和原始决策均保持可追溯。每个请求的延迟、调用次数和场景预算各不相同；套接字超时并非严格边界，超时情况被记录，超出场景预算的响应被拒绝。`--preload`拥有独立的加载延迟，不计入决策预算。无任何服务器或自动下载。

选择首先比较局部观测值，然后比较轨迹可能分叉的事件。验证通过：100%的结构化和法律决策，无任何援助，至少执行了一次非空的实际操作。按M8/M10自身质量进行字典排序，随后是延迟，再是磁盘大小。在独立测试前，选择已固定：M8 `qwen2.5:7b-instruct-q4_K_M`，M10 `qwen3:4b-instruct-2507-q4_K_M`。`--selection`加载已保存的参数和名称，然后通过`/api/tags`验证精确名称/哈希值；若哈希值发生变化，则拒绝。显式CLI选项优先；`--model`故意选择另一个模型，而无需验证初始选择的哈希值。

### 已知限制

- M7：适用于短期时间表；短窗口有时不可行，需使用FIFO援助。稳健性仅限于声明的日历和固定队列类别；若枚举被截断，则无最优证书，且无任何离群集合保证。
- M8：同步DSA可能震荡，缺乏总体收敛性和最优性的保证。对大ID的验证结果不利，失败的实例未被分配任务；模拟网络。
- M9：独立MAPF，未整合任务/维护/站点V1。优先级计划不完整且对顺序敏感；证书仅限于短期视界和吸收性目标。预算累计了A*、CBS和oracle的扩展；墙时通过协作方式控制。预算耗尽并不证明不可行性。oracle仅限于四个代理，十六个自由单元和十六个时钟周期。
- M10：精确的表格编码迁移性差，缺乏保证的马尔可夫状态。评估的实例中没有障碍、站点、暂停或延迟到达；在分布外的小数据集上也未证明任何已学习的表格泛化能力。
- Ollama：运行时间和负载依赖于硬件，合成的小数据集以及合法输出缺乏良好协调性的保证。Devstral 24B超出120秒预加载预算，未进行热质量度量；未证明总体优势。

比较严格遵循信息边界：M7 oracle离线，V1全局基线，M8/M10局部策略。合成的小领域，未证明总体优势。
